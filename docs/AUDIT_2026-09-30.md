# Technical Audit — 2026-09-30

Scope: full repository (code, documentation, GitHub issues) and the primary artifact itself.
Method: line-by-line code review; static parsing of all MATLAB files with MISS_HIT 0.9.44
(`mh_lint`); independent re-computation of every dataset fact with
`scripts/reference/audit_dataset_reference.py` (Python stdlib + NetworkX 3.6.1) on the artifact
with Git blob SHA `3afe9cbb4e313fb056f1b115c92a3f750f4698b9`.

**MATLAB was not available in the audit environment.** No MATLAB code was executed. See
[Verification status](#verification-status).

## 1. Summary

The repository had a good *foundation*: a clear research framing, an explicit non-criminality
stance, a MATLAB-first policy, a verified dataset choice and a sensible document skeleton. The
implementation was a first data slice (load → flatten → validate → degree features) with four
correctness bugs, one untestable test file, O(N·E) feature code and no analysis beyond degree
counts. Temporal, spatial, sequence, anomaly, pattern, explainability, evaluation and UI layers
existed only as empty folders and planning text.

The most consequential discovery was about the **data, not the code**: the offender network is
not an independent source of relational information. It is fully derivable from the crime records
(Section 3). That changes the graph model, the features, the ablation logic and what can be claimed.

### B. Data completeness
- Schema was inspected, but **cross-record consistency was never checked**. It is now: every
  crime has identical date/X/Y/`num_of_offenders` across its offenders (V50), `num_of_offenders`
  always equals the number of attached offenders (V51), and every link weight equals the number
  of shared crimes (V52–V54).
- Missing before: duplicate association rows, time-of-day resolution, implausible dates,
  reciprocity, self-loops, duplicate links, zero/non-integer weights, date heaping, isolated nodes.
  All are now checks (see `src/data/validateBurglaryNetwork.m`).

### C. Analytical completeness
Only degree features existed. Temporal, spatial, sequence and pattern analyses are now
implemented as separate, testable modules (Section 5).

### D. Statistical validity
- No baseline, no threshold rationale. Now: a transparent robust baseline, modified z-scores with
  the documented 3.5 cut-off (Iglewicz & Hoaglin 1993), explicit MAD=0 fallback, and an explicit
  *review budget* instead of a pseudo-statistical anomaly threshold (no labels exist).
- `mean_inter_event_days` was computed for offenders with 2 events (one gap) and `NaN` vs `0`
  semantics were mixed. Undefined features are now `NaN` with explicit minimum-event rules.
- Pre-2014 data (91 rows) and the right-censored last months are excluded from system-level
  temporal baselines, with reasons.

### E. Machine learning completeness
No model existed. Isolation Forest (`iforest`, fixed seed, `ContaminationFraction = 0`) is
compared with the baseline on the *same* prepared matrix. No labels exist, so there is no
train/test leakage in the supervised sense; the remaining leakage risk (look-ahead in temporal
scoring) is avoided by causal baselines and causal sequence states.

### F. Explainability

an exact additive share for the baseline, an occlusion delta for Isolation Forest, a dominant
feature group and generated text with a mandatory interpretation caveat.

## 3. New findings about the data (verified, reproducible)

All numbers: `python3 scripts/reference/audit_dataset_reference.py <json> --graph`.

1. **The directed graph is symmetric.** All 21,302 links come in reciprocal pairs with equal
   weight: 10,651 undirected relations. `directed=true` is a serialization property, not a
   semantic one. → The graph is modelled as undirected.
2. **Link weight = number of shared crimes, for every link**, and every pair of offenders sharing
   a crime is linked. The offender network is exactly the one-mode projection of the
   offender–crime bipartite graph. Consequences:
   - graph features are *derived from* co-offending counts, so "graph" and "co-offending"
     feature groups are not independent sources of evidence (stated in every ablation result);
   - every relation can be **time-stamped** (first/last shared crime), which makes a dynamic
     network, edge persistence and temporal playback possible — none of which the file offers
     directly.
3. **`num_of_offenders` is not independent information**: it equals the number of offenders
   attached to the crime in the file for all 24,087 crimes.
4. **Dates are day-resolution only** (0 of 34,156 non-midnight). Hour-of-day analysis is
   impossible; same-day ordering is a convention (numeric crime ID).
5. **Coverage is uneven**: 91 rows before 2014 (1 in 2010, 2 in 2011, 5 in 2012, 83 in 2013),
   ~4.8–5.6k rows per year 2014–2019, and 2020 ends on 2020-09-28 with September at about half a
   normal month. The data are *solved* cases, so recent months are right-censored by solving delay.
6. **Mild date heaping**: day 1 of the month has 17.7 % more offender-crime rows than the
   average of days 2–28 (16 % at crime level); possibly imputed dates. Reported as V61.
7. **Heavy sparsity**: 66 % of offenders (11,446) have one crime; 7,597 (44 %) have no
   co-offender; 3,260 have ≥ 3 crimes (the anomaly-model population). Largest connected component:
   518 offenders; 10,468 components in total; maximum k-core 12; 1,156 articulation points.
8. **Repeated sites**: 24,087 crimes occupy 19,509 distinct normalized (X, Y) points.
9. **July is the busiest month** in aggregate; a causal 12-month rolling median flags July 2016
   and July 2019 (reference computation), which is plausibly seasonality rather than an anomaly.
   This is a documented limitation and an open task (seasonal baseline).
10. **License**: the upstream repository carries a BSD-3-Clause-style "ROXANNE" license
    (Copyright 2021 Consortium Board ROXANNE); the dataset documentation states anonymization
    under Israeli law and GDPR with legal-advisor approval. Citation: Ahmadi et al. (2023).

## 4. Missing ideas that were added (and why)

| Idea | Why it matters | Where |
|---|---|---|
| Time-stamped relations / dynamic graph | turns a static picture into network evolution, enables replay | `buildRelationTable`, `computeDynamicGraphStats`, `buildGraphSnapshot` |
| Eligibility rule (≥ 3 crimes) | 66 % of offenders have no temporal history; scoring them would make "insufficient history" look "normal" | `runAnomalyDetection` |
| Derived sequence alphabet | the data have no event types; partner novelty × spatial move is observable and causal | `src/sequence/` |
| Causal temporal baselines | avoids look-ahead; usable for replay | `detectTemporalAnomalies` |
| Review budget instead of a "risk threshold" | no labels exist; a budget is honest and tunable | `applyReviewBudget` |
| Feature registry | one definition drives scaling, ablation, explanation text and docs | `featureRegistry` |
| Occlusion attribution | Isolation Forest is otherwise a black box | `explainAnomalies` |
| Synthetic injection per feature group | the only controlled way to test sensitivity without labels | `injectSyntheticAnomalies`, `runExperiments` |
| Independent reference audit | the only execution-based verification possible without MATLAB | `scripts/reference/` |
| Space–time Poisson excess on a normalized grid | spatial analysis that does not require de-normalizing coordinates | `computeSpatialHotspots` |

Considered and **not** added: LOF / One-Class SVM (no evaluation signal that would justify a
third model), community detection (no built-in Louvain in MATLAB; components + k-core + cut
vertices cover the structural questions for a 518-node largest component), crime-network
artifact (would duplicate the projection), audio narration (low analytical value; a single
optional audio cue exists).
