# GitHub Workflow

## Branches
- `main`: stable deliverable
- `dev`: integration branch
- feature branches: one logical change at a time

## Commit style
Use concise conventional prefixes:
- `feat:` new capability
- `fix:` bug fix
- `refactor:` code structure
- `test:` testing
- `docs:` documentation
- `exp:` experiment

## Pull request expectation
Every non-trivial change should mention:
- problem,
- approach,
- files changed,
- verification,
- known limitations.

## Data policy
Never commit raw datasets unless redistribution rights are explicitly confirmed and documented.
